# Mamaearth Returns & Growth Intelligence Pipeline

Capstone project — *Data Analytics with AI & Gen AI* (Masai × E&ICT Academy, IIT Roorkee).

**Business question:** Where are returns really coming from, and what is the true revenue picture once the data is cleaned?

**Short answer:** Returns are concentrated in **Cash-on-Delivery orders from Tier-2 cities** (54.5% return rate, against 44.4% for COD overall). Raw revenue was overstated by five double-submitted orders, and January only *looked* like the best month because of two bulk orders. March is the true peak.

The project is one pipeline in three layers. Each layer feeds the next, and **no layer reports a number it did not compute itself or receive from the layer before it.**

```
 data/*.csv  (raw, never edited)
     │
     ├──► 1. SQL layer       sql/        SQLite schema, load, 9 business reports on the raw data
     │
     └──► 2. Python layer    analysis/   pandas cleaning, reconciliation to SQL, EDA, 2 charts
               │
               └── writes narrator/findings.json  (verified figures, written by code)
                         │
                         └──► 3. GenAI layer   narrator/   Gemini SCR narrative + offline fallback
```

## Setup (once)

**Requirements:** Python 3.11 or later, and the `sqlite3` command-line tool (version 3.32 or later, for `.import --skip`).

From the repository root:

```bash
pip install -r requirements.txt
```

All commands below are run **from the repository root**, on Windows PowerShell, macOS or Linux.

## Run order

### Step 1 — SQL layer (`sql/`)

Build the database and run the reports, **in this order**:

```bash
sqlite3 mamaearth.db ".read sql/schema.sql"
sqlite3 mamaearth.db ".read sql/seed_data.sql"
sqlite3 mamaearth.db ".read sql/reports.sql"
```

- `schema.sql` drops and recreates the three tables, so every run starts from a clean slate.
- `seed_data.sql` loads the CSVs with `.import --skip 1` (so the header row is not loaded as data), converts blank cells to real `NULL`, and prints its own checks. Expect **45 / 16 / 180** rows, **12** NULL discounts and **15** NULL ratings.
- `reports.sql` runs reports (a)–(i) on the **raw** data. Each query's exact output is pasted as a comment above it.
- Report (i) adds a column with `ALTER TABLE`, so to re-run the SQL layer always repeat **all three commands** in order. Running `reports.sql` on its own a second time fails with `duplicate column name`, which is expected.
- `mamaearth.db` is a generated file and is not committed (see `.gitignore`).

### Step 2 — Python analysis layer (`analysis/`)

```bash
python analysis/clean_and_eda.py
python analysis/visualize.py
```

- `clean_and_eda.py` reads the **raw CSVs directly** (not the database), so Step 1 and Step 2 can run in either order. It prints every intermediate result, Tasks 1–10:
  standardise casing → remove duplicates → impute → merge and reconcile with SQL → flag outliers → hypothesis test → segmentation → correlation → monthly trend.
- At the end it **writes `narrator/findings.json`**, the verified figures that the next layer uses. This file is generated by code and is never typed by hand.
- `visualize.py` reads `findings.json` and saves both PNGs to `visualizations/`.
- Both scripts are deterministic: re-running them regenerates identical numbers, an identical `findings.json` and byte-identical PNGs.

### Step 3 — GenAI narrator layer (`narrator/`)

```bash
python narrator/generate_narrative.py
```

The script reads `findings.json`, produces a Situation–Complication–Resolution narrative, and runs a numeric accuracy check. It works in two modes.

**Option A — no API key (offline, zero setup).** Just run the command above. With no key set, it uses a template-based narrative built from `findings.json`. It needs no network, no key and no spend, and all five key figures are guaranteed to be present.

**Option B — with a free Gemini API key.** Get a free key from [Google AI Studio](https://aistudio.google.com/) (free tier — no paid key is needed). Set it as an environment variable **in your terminal only** — never in a file in this repo:

```powershell
# Windows PowerShell (lasts until the window is closed)
$env:GEMINI_API_KEY = "your-key-here"
python narrator/generate_narrative.py
```

```bash
# macOS / Linux
export GEMINI_API_KEY="your-key-here"
python narrator/generate_narrative.py
```

- The default model is `gemini-3.5-flash-lite`. If Google retires it, set `GEMINI_MODEL` to the current free Flash model shown in AI Studio. No code change is needed.
- The call uses `temperature=0.0`, `max_output_tokens=2048` and a 30-second timeout, and is wrapped in `try/except`. If the call fails for any reason (bad key, no network, quota, retired model), the script prints the reason and **falls back to the offline narrative**.
- A successful Gemini run is saved to `narrator/sample_output.txt`. Offline runs never overwrite it.

**Accuracy check.** Every run checks the narrative for these five figures, after removing commas: cleaned revenue **97,358.30**, COD return rate **44.4**, COD + Tier-2 rate **54.5**, duplicate delta **2,501.90**, and **March** with **20,318.90**. It prints PASS or FAIL for each one. It checks both the narrative just produced and the saved Gemini sample (`sample_output.txt`).

## Cleaning decisions and assumptions

- **Source data is never edited.** All cleaning happens in `clean_and_eda.py`.
- **Order of cleaning:** standardise casing → remove duplicates → impute → merge → flag outliers → trend. Duplicates are removed before imputing so they cannot bias the median, and outliers are flagged before the monthly trend.
- **Duplicates** are detected on the natural key (every column except `order_id`, because double-submits got new IDs). The first occurrence is kept.
- **Missing discount → 0** (business rule: no promo code applied). **Missing rating → median (3.0)** of the de-duplicated data.
- **Outliers are flagged** (`is_outlier`), not dropped. They may be genuine bulk purchases, so results are shown both with and without them.
- **SQL uses the raw data and Python uses the cleaned data.** The difference between them is reconciled exactly in Part 2 Task 5.

## Limitations

- Segment sizes are small (22–68 orders), so return rates are directional. One extra return moves the COD + Tier-2 rate by about 4.5 points.
- Task 7 compares return rates descriptively. It is not a formal significance test.
- The 15 imputed ratings (all set to 3.0) slightly dampen correlations involving `rating`.
- LLM wording is not byte-identical between runs, which is why a saved Gemini sample is checked and why the offline template exists.

## Security

The Gemini API key is read only from the `GEMINI_API_KEY` environment variable. No key is stored anywhere in this repository, and `.env` files are excluded by `.gitignore`.
